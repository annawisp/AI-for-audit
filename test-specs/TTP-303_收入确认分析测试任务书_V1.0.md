# TTP-303 收入确认分析 Capability 测试任务书 V1.0

> 对应搭建任务：TASK-303 收入确认分析 Capability  
> 所属阶段：Stage 3 文档处理与审计能力模块  
> 测试对象：收入确认分析 Capability  
> 文档类型：测试任务书 / Test Specification  
> 版本：V1.0

## 1. 测试目标

验证 TASK-303 是否能够基于合同要素、Project Context 及可选收入记录，完成收入确认相关分析，并输出符合统一 Evidence Object 结构的结果。

重点验证：

- 仅合同场景下，系统可以完成合同层面的收入确认分析。
- 缺少收入记录时，不会导致整体失败。
- 收入确认分析采用“触发 → 分析 → 结论”的三态判断结构。
- 每个判断节点支持人工复核状态。
- 输出包含 Coverage、Limitations 和影响说明。
- 输出符合统一 Evidence Object Schema。
- 系统正确区分资料缺失、字段不足、冲突证据和不适用情形。

## 2. 测试范围

### 2.1 范围内

- 收入确认分析 Capability 的独立运行能力。
- 基于 TASK-302 合同要素提取结果执行收入确认分析。
- 基于 Project Context 补充分析条件。
- 可选收入记录参与分析。
- 合同层面收入确认判断。
- 字段不足、收入记录缺失、冲突条款等部分输入场景。
- Evidence Object 输出结构。
- Coverage、Limitations、影响说明。
- 人工复核状态。
- 自动化测试与 Foundation CI 兼容性。

### 2.2 范围外

- TASK-304 收入风险识别。
- TASK-305 数据核对与异常检测。
- 完整审计程序编排器。
- 九态状态机完整实现。
- 底稿生成。
- 真实 LLM 判断准确率评估。
- 复杂会计准则全量覆盖。

## 3. 验收口径

TASK-303 通过不要求完成完整收入审计结论。通过标准为：在仅有合同或部分资料的情况下，系统能完成最大可执行范围内的收入确认分析；对不能判断的部分明确标记为限制、证据不足或待复核；输出符合 Evidence Object 的结构化结果，并包含 Coverage、Limitations 和影响说明。

|---|---:|---|
| project_id | 必选 | 项目 ID |
| document_id / contract evidence reference | 必选 | 合同文档或 TASK-302 输出引用 |

TASK-303 输出应至少包含：

- status
- analysis_nodes / nodes

- limitations
- impact_summary / impact

- trigger

- confidence_level
- confidence_basis 或 supporting_fields
- source_references 或支持字段/证据来源引用

## 6. 核心验收标准

### AC-303-01：Capability 可独立运行

- TASK-303 不依赖完整 Agent 串行流程。
- TASK-303 不强制依赖 TASK-304 或 TASK-305。
- TASK-303 可基于 TASK-302 输出独立运行。
- Capability 可被自动化测试直接调用。

### AC-303-02：仅合同场景可完成合同层面分析

- 请求不报错。
- 分析结果状态不得整体失败。
- 合同层面节点可以完成。
- 收入记录相关节点应标记为受限、未覆盖或证据不足。
- Coverage 明确说明仅覆盖合同层面分析。

### AC-303-03：三态判断结构

- 每个节点包含 trigger。
- 每个节点包含 analysis。
- 每个节点包含 conclusion。
- 未触发事项不得生成无依据结论。
- 已触发但证据不足事项应进入 ABSTAINED / PENDING_REVIEW / NEED_MORE_EVIDENCE 等状态。

### AC-303-04：收入确认分析节点覆盖

至少覆盖：履约义务是否清晰、收入确认时点、验收条件影响、收款条件影响、交易价格是否明确、特殊条款是否影响收入确认、缺少收入记录时是否仅能形成合同层面结论。

### AC-303-05：缺少收入记录不导致整体失败

- 合同层面分析继续执行。
- 收入记录相关分析节点标记为受限。
- Limitations 中说明未覆盖收入明细差异分析。
- 影响说明中解释该限制对收入确认结论的影响。
- 不得把“收入记录未提供”解释为“审计师未执行程序”。

### AC-303-06：Evidence Object 输出

- Evidence Object 包含 evidence_id、project_id、source、extracted_value、conclusion、execution_status、node_status、judgment_status、confidence_level、confidence_basis。
- source 应指向 capability:revenue_recognition_analysis 或等价来源。

### AC-303-07：Coverage、Limitations 与影响说明

- 每次分析输出必须包含 Coverage。
- 每次分析输出必须包含 Limitations。
- 每次分析输出必须包含影响说明。
- 正常输出、部分输出、受限输出均需包含上述内容。

### AC-303-08：人工复核状态

- 节点可标记 requires_review=true。
- AI 已分析但需专业判断时，允许 node_status=ANALYZED 或 partial 与 judgment_status=PENDING_REVIEW 并存。
- 复杂收入确认判断不得直接标为最终确认。

### AC-303-09：字段不足与冲突处理

- 字段缺失只影响依赖该字段的节点。
- 冲突条款进入 PENDING_REVIEW 或 CONFLICTING_EVIDENCE。
- 不得因单个字段缺失导致整体失败。
- 不得编造缺失字段的结论。

### AC-303-10：收入记录可选参与

- 有收入记录时，可执行基础一致性分析。
- 收入记录字段不足时，只影响依赖该字段的节点。
- 收入记录异常不得覆盖合同层面结论。
- 输出应说明收入记录是否参与分析。

## 7. 测试用例

| 用例编号 | 场景 | 预期结果 |
|---|---|---|
| TC-303-01 | 仅合同要素，无收入记录 | 合同层面分析完成，收入记录节点 ABSTAINED，输出 Coverage/Limitations/impact |
| TC-303-02 | 合同要素完整，收入确认时点清晰 | 收入确认时点节点完成分析，结论有依据 |
| TC-303-03 | 合同缺少验收条款 | 验收条件节点 PARTIAL/ABSTAINED，不整体失败 |
| TC-303-04 | 合同存在冲突条款 | 相关节点 PENDING_REVIEW 或 REQUIRES_REVIEW |
| TC-303-05 | 收入记录缺失 | 合同层面继续执行，收入记录分析未覆盖 |
| TC-303-06 | 收入记录存在但字段不足 | 相关节点 PARTIAL，其他节点继续执行 |
| TC-303-07 | Evidence Object Schema 校验 | 结构符合统一 Evidence Object |
| TC-303-08 | Coverage/Limitations 必填校验 | 所有输出均包含 Coverage、Limitations、impact |
| TC-303-09 | 不存在项目 | 返回 404 或等价业务错误，包含 trace_id |
| TC-303-10 | 无 TASK-302 合同要素输入 | 返回明确受限状态或错误，不生成虚假结论 |

## 8. 自动化测试要求

- TASK-303 Capability 单元测试。
- 收入确认分析 API 集成测试。
- 仅合同输入测试。

- 字段缺失测试。
- 冲突条款测试。
- Evidence Object Schema 测试。

## 9. CI 验收要求

远端 GitHub Action / Foundation CI 应通过：

- Backend ruff check
- Backend pytest
- Frontend build
- Windows backend test
- Ubuntu backend test

若 TASK-303 不涉及前端变更，前端 build 仍不得被破坏。

## 10. 不通过判定

出现以下任一情况，TASK-303 判定为不通过：

- 仅合同输入时整体失败。
- 缺少收入记录时整体失败。
- 输出不包含 Coverage。
- 输出不包含 Limitations。
- 输出不包含影响说明。
- 收入确认结论无法转换为 Evidence Object。
- 字段缺失时系统编造结论。
- 冲突条款未进入人工复核。
- 系统把“资料未提供”解释为“审计师未执行程序”。
- 远端 Foundation CI 未通过。
