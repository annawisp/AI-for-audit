# TTP-201 Project Context MVP 测试任务书 V1.0

## 1. 测试对象

- 项目：AI for audit
- 任务：TASK-201 Project Context MVP
- 测试范围：项目级上下文数据结构、上下文 API、版本化保存、当前版本读取、历史版本查询、与 TASK-101/102 基础工程能力的兼容性

## 2. 验收目标

TASK-201 应在现有项目与基础 API 之上，提供最小可用的 Project Context 能力，使后续审计程序、证据对象和智能体编排可以读取项目级背景信息。

验收目标包括：

1. 能为指定项目创建或更新 Project Context。
2. Project Context 至少覆盖 MVP 所需核心字段，并允许空字段以支持逐步补全。
3. 每次写入应生成不可变版本记录。
4. 当前版本应可直接读取。
5. 历史版本应可查询，版本号连续递增。
6. 应记录变更人、变更原因和变更章节。
7. 不存在的项目不得创建上下文，应返回清晰错误。
8. 不得破坏 TASK-101/102 已有健康检查、项目、文档、数据库和文件上传能力。

## 3. 测试环境

- Python：3.12 或 CI 指定版本
- 后端依赖：`backend/requirements.lock`
- 数据库：测试临时 SQLite 文件
- 测试数据：人工合成或脱敏样例，禁止真实客户资料

## 4. 自动化测试命令

在仓库根目录执行：

```bash
cd backend
ruff check .
pytest
```

如需单独执行 TASK-201 相关测试，可执行：

```bash
cd backend
pytest tests/test_project_context.py
```

如果测试文件命名不同，应以仓库中实际 TASK-201 测试文件名为准，但必须覆盖本任务书第 5 节的验收点。

## 5. 功能测试用例

| 编号 | 测试项 | 操作 | 预期结果 |
|---|---|---|---|
| TTP-201-001 | 创建项目上下文 | 先创建项目，再调用 Project Context 创建/更新接口提交 MVP 上下文字段 | 返回 200 或 201；响应包含 `project_id`、`version=1`、上下文 payload、`is_current=true` |
| TTP-201-002 | 读取当前上下文 | 创建上下文后调用当前上下文读取接口 | 返回最新版本；payload 与最近一次写入一致 |
| TTP-201-003 | 版本递增 | 对同一项目连续写入两次上下文 | 第二次返回 `version=2`；第一版保留在历史记录中；只有第二版为当前版本 |
| TTP-201-004 | 历史版本查询 | 调用版本列表或指定版本读取接口 | 能读取 version 1 和 version 2；内容分别保持写入时状态 |
| TTP-201-005 | 变更章节记录 | 第二次写入只修改部分章节 | `changed_sections` 只包含实际变化的章节；未变化章节不应被错误标记 |
| TTP-201-006 | 变更元数据 | 写入时提交 `changed_by` 和 `change_reason` | 响应和数据库记录保留变更人、变更原因 |
| TTP-201-007 | 空字段兼容 | 提交只包含部分上下文字段的 payload | API 不因非必填字段缺失失败；缺失字段保持为空或默认结构 |
| TTP-201-008 | 不存在项目校验 | 对不存在的 `project_id` 写入或读取上下文 | 返回 404，错误信息明确为项目不存在或上下文不存在 |
| TTP-201-009 | 基础能力回归 | 执行全部 pytest | TASK-101/102 既有测试仍通过 |

## 6. 数据库与持久化验收

1. 数据库应存在 Project Context 版本表或等价持久化结构。
2. 每次写入应新增版本记录，不应覆盖历史版本。
3. 同一项目只有一个当前版本。
4. `project_id + version` 应具备唯一性。
5. payload 应以结构化 JSON 或等价形式保存，读取后字段不丢失。

## 7. 非功能与安全测试

1. 不允许提交 `.env`、日志、数据库文件、上传目录、构建产物或真实客户资料。
2. 上下文 payload 中的测试内容必须为合成或脱敏内容。
3. API 错误应返回明确状态码，不应出现未处理异常导致 500。
4. Project Context 不应在本任务中执行审计判断或生成正式审计结论。

## 8. 验收通过标准

满足以下条件可判定 TASK-201 代码验收通过：

- `ruff check .` 通过。
- TASK-201 Project Context 相关自动化测试通过。
- 全量 `pytest` 通过，且不破坏 TASK-101/102 既有能力。
- GitHub Actions 远程 CI 通过。
- 未发现敏感信息、构建产物或本地运行文件被提交。

## 9. 已知限制

- TASK-201 只提供项目级上下文 MVP，不负责完整审计程序编排。
- 当前上下文用于后续智能体和审计能力读取，不代表已完成收入审计判断。
- 字段范围可随后续 TASK 扩展，但历史版本语义应保持兼容。
